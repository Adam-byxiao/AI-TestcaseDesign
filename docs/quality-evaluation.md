## 5. 评测方法

### 5.1 五维评分

| 维度 | 权重 | 关注点 |
|---|---:|---|
| 覆盖度 | 25% | 需求是否有缺口／越界；量化事实是否落地；维度是否有分层 |
| 准确度 | 25% | 契约标识符与路由是否真实；是否引入输入之外的术语 |
| 结构合理性 | 20% | 字段完整性；映射是否干净；设计方法与维度是否匹配 |
| 重复性 | 15% | 标题/步骤签名重复；跨批次重复；语义近似 |
| 可读性 | 15% | 断言覆盖；导出物可读性；字段填充率 |

### 5.2 证据要求：全部结论来自**逐条枚举**

- **契约合规**：340 个标注逐条按「种类 + 值」**独立复算**，不依赖门禁自身的结论
- **覆盖度**：需求逐条对照追溯矩阵；PRD 主章节逐节核验
- **重复性**：同签名用例**逐组人工判定**（区分「合法等价类」与「真重复」）
- **可读性**：导出产物逐项检索机器标记；无断言用例逐条枚举
- **准确度**：专用术语全产物检索；路由逐条比对契约页面键

### 5.3 方法论教训（累计）

1. **「门禁报告 0 问题」≠「产物合规」** —— 必须独立复核门禁自身的能力。
   中期评测正是因为独立复算，才发现 17 处越界被门禁放行。
2. **同步骤签名 ≠ 重复** —— 等价类与边界值本就「同流程、不同数据」，
   判定重复必须结合设计意图，否则会误伤正确的测试设计。
3. **对比评测必须确认基准一致** —— 否则会把「输入变干净」误记为「模型变强」。
4. **接线必须单独测** —— 纯函数测试全绿不代表它被调用过（本项目因此漏报过多次，
   详见 [development.md](development.md)）。
5. **量化结论必须以逐条枚举为准** —— 早期用关键词统计得出的「check 误用 89%」
   在逐条枚举后修正为 87%，且**误用的性质**（词表缺口而非模型不听话）只有枚举才看得出来。

## 6. 如何复现评测

```bash
# 1. 用同一份 PRD 生成（真实模型）
prd2tc generate --prd <PRD.md> --product <P> --version v1 --out output

# 2. 产物位置
output/<P>/v1/{analysis,plan,cases}/

# 3. 关键核对项（逐条枚举，不要只看汇总）
#    - cases/traceability.json：unknownReferences / duplicateMappings / summary
#    - analysis/ui-spec.json  ← 契约真值，用于逐条比对用例 target
#    - cases/cases/*.json     ← 机读用例（结构化步骤）
#    - cases/用例集.xlsx      ← 人类可读产物（自然语言步骤）
```

评测时请**先确认基准 PRD 是原件而非扩写版**，并记录运行 ID 以便追溯。
