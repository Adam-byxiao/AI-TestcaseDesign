# 测试设计原理与硬约束（阶段 1/2 强制遵循）

> **约束分级**：
> - **[必须]**：违反即不合格，输出前必须通过「6. 输出自检门」；
> - **[禁止]**：出现即不合格；
> - **[尽量]**：不满足必须说明理由。
>
> 适用阶段：**1 需求分析 / 2 测试方案**（阶段 3 的用例级约束见 `04-case-constraints.md`）。
> 每阶段输出前必须执行第 6 节自检门，未通过不得输出。

## 1. 需求可测性（必须）

- [必须] 每个需求点必须落到「可断言的 UI 元素 / 数据 / 状态变化」。
- [必须] 需求模糊或不可测时，必须标注「待确认」，并给出建议的确认口径。
- [禁止] 臆造验收标准、编造需求中不存在的规则。
- **条件分支**（按需求特征强制细化验收标准）：
  - 涉及金额 → 必须给出精确数值与计算式；
  - 涉及状态 → 必须列出状态取值与迁移；
  - 涉及权限/角色 → 必须列出角色清单与可见性差异；
  - 涉及输入校验 → 必须列出非法输入类。
- **检查**：逐条 REQ 自问「能写出可断言的步骤与预期吗？」——不能则按上条处理，禁止跳过。

## 2. 测试设计方法（必须标注）

- [必须] 每条用例标注 `design_method`（等价类划分 / 边界值分析 / 判定表 / 状态迁移 / 场景法 / 错误推测）。
- **方法选用条件**（按需求特征触发，不满足即视为方法空白）：
  - 输入存在取值域 → 等价类划分 + 边界值分析；
  - 多条件组合影响同一结果 → 判定表；
  - 存在状态机 / 状态切换 / 账号状态 → 状态迁移；
  - 存在业务流程 / 用户旅程 → 场景法（happy path + 备选流 + 异常流）；
  - 存在历史缺陷高发点 / 易错点 → 错误推测。
- [禁止] 无方法依据的"拍脑袋"用例；用例内容必须与方法对应。
- **检查**：每个 REQ 覆盖的方法是否成体系（正向 / 反向 / 边界 / 异常各有着落）。

## 3. 覆盖维度（必须）

- [必须] 需求覆盖：每个 REQ-* 至少一条用例；未覆盖必须列明原因（如验证码需人工）。
- [必须] 数据覆盖：边界数据必测（门槛 ±1、数量 1 与库存上限、价格区间 min/max、空值）。
- [必须] 状态覆盖：关键状态迁移全路径（如 normal→disabled、空购物车→非空→空）。
- **检查**：traceability 表是否 100%；边界用例是否存在；状态用例是否成环。

## 4. 用例质量属性（必须 / 禁止）

- [必须] **独立**：不依赖其他用例的执行顺序与共享可变状态。
- [必须] **可执行**：步骤粒度到「元素 + 动作」，target 用「页面元素中文名 (data-testid)」格式。
- [必须] **可验证**：每条预期可断言（URL / 文本 / 状态 / 金额精确值，金额格式 ¥ 千分位 2 位小数）。
- [禁止] 模糊步骤（"随便点点""执行操作"）。
- [禁止] 不可验证预期（"表现正常""无异常"）。
- [必须] **相似不等于重复**：对象不同、边界值不同、断言不同的用例**应保留**；同一功能点的多种输入、多个状态、多个边界值得单点验证。
- [禁止] 重复用例——判定口径为**三要素完全一致**：模块 + 步骤序列（动作与目标）+ 预期序列。三者全同才算重复。
- [禁止] 用例互相依赖（用例 B 需要用例 A 先执行）；[必须] 每条用例可独立执行。
- [禁止] 为凑数量生成的同质用例（title 不同但步骤与预期实质相同）。
- **检查**：逐条过反模式清单；同模块内两两对比去重。

## 5. 优先级与风险导向（必须）

- **P0 判定条件**（任一命中即 P0）：核心链路 / 安全 / 金额 / 权限。
- P1：主要功能；P2：边界 / 次要；P3：低频 / 体验。
- [必须] P0 用例必带 `@smoke`；全量带 `@regression`；按模块带模块标签（@auth/@cart/@checkout…）。
- [必须] 测试方案按风险排序：高风险模块（金额 / 权限 / 状态）用例密度更高、全部覆盖；低风险冒烟覆盖。
- **检查**：方案中的优先级口径与阶段 1 分析一致；P0 覆盖核心链路闭环。

## 6. 输出自检门（每阶段输出前强制）

| 阶段 | 自检项（全部通过才允许输出） |
| --- | --- |
| 1 需求分析 | REQ 编号与 PRD 一致无遗漏；每条可断言；模糊项已标「待确认」；无臆造规则 |
| 2 测试方案 | 范围/策略/风险/环境数据/准入准出齐全；优先级口径与阶段 1 一致；每层策略可落到具体用例类别 |
| 3 用例生成 | 字段校验全过（id 格式 / module / priority / tags / requirement / steps / expected）；P0 带 @smoke；无反模式；traceability 全覆盖；design_method 已标注 |

- **执行规则**：任一自检项不通过 → 必须修正后重新生成，[禁止] 带病输出。
- **质量优先**：无法一次生成全部内容时，宁可少而合格，不做多而劣质。
- 输出前先在心里逐项核对自检表，再产出最终结果。
